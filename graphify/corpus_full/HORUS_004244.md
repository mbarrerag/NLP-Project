# A metric for measuring technical debt based on analysis of the most used. Case study of the Square repository

Technical debt is a main component of the cost of ownership of the application, it has become one of the most important metaphors to express the development shortcuts, which cause the degradation of the internal quality of the software. It is necessary to emphasize that, there are metrics of open source which provide numerical data in some software products and which in turn allow to measure the index of maintenance, cyclomatic complexity, Depth of inheritance, Coupling of classes, Source lines, Executable code lines where developers can identify risks and make continuous monitoring. However, the literature informs of several metrics of software for product lines and process, others oriented to objects. In fact, a centralized search of several repositories of open code in the GitHub platform is carried out with the aim of fulfilling the need exposed according to the criteria defined where the medimetric is already selected nine repositories specifically with the language Python obtaining A if a higher score of open source (square/square-python-sdk) for the application of the metric, which is already a project of applied to the medimetric and applied to all repository of the Python The results of the survey were published in the Official Journal of the European Communities
